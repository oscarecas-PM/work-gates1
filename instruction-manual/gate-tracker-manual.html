1. Overview

Gate Tracker is a visual factory tool that shows where manufacturing work orders currently sit in a gate sequence. In a physical shop, gates correspond to racks or stations where hardware resides as it moves through its manufacturing operations. Gate Tracker provides a clear, at-a-glance view of which rack each piece of hardware belongs on and where it is in its overall process flow.

Key Concepts

Gate
A numbered station or rack in the manufacturing flow. Work orders move from gate to gate as operations are completed.
Work Order
A manufacturing order tracked through the MES system, identified by an Order Number (e.g., "000123456789").
Decoder Ring
A mapping file that tells the tool which MES operations belong to which gates. Created and maintained manually (or using the Decoder Ring Builder companion tool).
Program
The program a part number belongs to (e.g., "P-Program", "N-Program"). Used for color coding and filtering.
Part Number
The specific part being manufactured. Each part number has its own set of operations defined in the Decoder Ring.
Note
Gate Tracker runs entirely in your browser. No data leaves your machine — all processing is done client-side. Nothing is stored between sessions; you must reload your files each time.

2. Getting Started

2.1 Required Files

Gate Tracker accepts up to four CSV files. The first two are required; the last two are optional.

1. Gate Decoder Ring CSV (required)

Maps each part number's MES operations to numbered gates. This file is created and maintained manually or using the Decoder Ring Builder tool.

Part No., Part Name, Gate Number, Gate Name, Oper No., Work Dept, Modifier
  • Part No. — The part number this mapping applies to
  • Gate Number — The gate (rack) number where this operation's hardware should reside
  • Gate Name — A descriptive name for the gate
  • Oper No. — The MES operation number (bare format, e.g., "50" not "0050")
  • Modifier — Set to "ignore" to skip this operation during gate placement

2. Daily Upload CSV (required)

A snapshot from the MES system containing all active work order operations. Typically contains approximately 7,500 rows. The new data source exports this as a tab-delimited file (with a .csv extension). Gate Tracker auto-detects the delimiter.

Order No, Operation No, Operation title, Operation Status, Part Number, Program, Serial Numbers, Hold Status, Avg. DaysCurrentOper, Work Department, ...
  • The file contains approximately 42 columns total; Gate Tracker uses the 10 listed above
  • Operation Status values include: ACTIVE, IN QUEUE, PENDING, COMPLETE
  • Hold Status — If populated, indicates the order is on hold

3. Gate Technicians CSV (optional)

Maps technician names to gates. When loaded, technician names appear in Gate View headers.

Gate Number, Gate Name, Tech Name, Priority
  • Priority — Controls display order of technicians within each gate header (lower number = listed first)
Creating the Gate Technicians File

This file must be created manually. Open a spreadsheet (Excel, Google Sheets, etc.) and create four columns: Gate Number, Gate Name, Tech Name, and Priority. Add one row per technician-gate assignment. If a gate has multiple technicians, add a separate row for each with a different priority number (1 = primary, 2 = secondary, etc.).

Example:

Gate NumberGate NameTech NamePriority
1ReceivingMike Johnson1
2CNC MachiningSarah Chen1
2CNC MachiningTom Rivera2
3Deburr / QAJohn Smith1

Save as a .csv file (comma-delimited). The gate numbers and names should match those used in your Decoder Ring.

4. Mobile Audit CSV (optional)

Output from the Mobile Audit tool (see Section 7). When loaded, this file drives the Gate View placement — cards appear in the gates where hardware was physically scanned.

Gate Number, Order No., Part No., Serial No., Technician
Important
Without a Mobile Audit CSV, the Gate View will show a placeholder message instead of gate sections. The audit file is what tells the tool where hardware physically is.

2.2 Loading Files

📄
Screenshot: File Input Area
The top of the Gate Tracker page showing four file input boxes labeled 1 through 4, each with column descriptions and a file chooser button.
  1. Open gate-tracker-21.html in Chrome or Edge.
  2. In the "1. Gate Decoder Ring" box, click the file chooser and select your Decoder Ring CSV. A green status message will confirm the number of rows loaded (e.g., "Loaded 45 rows").
  3. In the "2. Daily Upload" box, load the daily MES export file. Verify the row count matches expectations (typically around 7,500 rows).
  4. (Optional) Load the Gate Technicians file and Mobile Audit CSV in boxes 3 and 4.
  5. The "Include Unmapped Operations" checkbox is checked by default. Uncheck it to skip orders whose part numbers are not in the Decoder Ring.
  6. Click the blue Process button. The button enables once both required files are loaded.

After processing, several additional buttons appear:

  • Print / Export PDF — Opens the browser print dialog
  • Save Snapshot — Downloads a self-contained interactive HTML file
  • Generate Mobile Audit — Creates a mobile-friendly audit tool

Navigation links ("Jump to Detail View" and "Jump to Unmapped Operations") also appear below the buttons for quick scrolling.

4. Gate View

The Gate View is the primary display of Gate Tracker. It shows work order cards organized into gate sections based on where hardware was physically scanned during the most recent mobile audit.

📈
Screenshot: Gate View
The Gate View showing multiple gate sections (Hold, Gate 1, Gate 2, etc.) with colored work order cards inside each section. Gate headers display the gate number, name, and assigned technicians.

Gate Sections

Gates appear in this order from top to bottom:

  1. Hold (red header) — Orders with a hold status
  2. Numbered gates in ascending order (dark header) — Each shows the gate number, gate name, and assigned technicians
  3. "Not found on a rack" (amber header, collapsible) — Active orders that were not scanned during the audit

Card Anatomy

Each card in the Gate View represents one work order and displays:

  • Order Number (bold, top line)
  • Part Number with part name
  • Serial Number(s) if available
  • Hold Status (red text, if applicable)
  • Avg days at current operation (bottom of card)
  • Technician assignment ("with [Tech Name]") when a specific tech was recorded

Color Coding

Cards are colored by program. The color is determined by the first letter of the program name:

  • Programs starting with P — Blue tones
  • Programs starting with N — Purple tones
  • Other programs — Assigned from a consistent color palette

Border Labels

Some cards have colored borders and labels indicating special conditions:

  • Red border + "DR Operations" — The order has active operations in the 7000–7999 range (Decoder Ring operations). This takes priority over the QA label.
  • Blue border + "QA Operations" — The order has active or in-queue operations in a QA work department (ending in "_QA"). Only shown when there is no DR Operations label.
  • Amber "Missing from daily upload" — The order was scanned in the audit but does not appear in the daily upload data.

"Not Found on a Rack" Section

🔍
Screenshot: "Not Found on a Rack" Section (Expanded)
The amber-colored collapsible section expanded to show work order cards for orders that are active in the daily upload but were not scanned during the mobile audit. A triangle icon indicates the expand/collapse state.

This section collects all active work orders that were not scanned during the mobile audit. It is collapsed by default — click the amber header bar to expand or collapse it. The triangle icon indicates the current state.

Cards in this section are sorted by: Program, then DR operations first, then Part Number, then Order Number.

Tip
If an order appears in "Not found on a rack," it may have been missed during the audit, or the hardware may have been moved. Check the physical location and include it in the next audit.

4.1 Split Location Warnings

⚠
Screenshot: Multi-Gate Warning Labels
Close-up of work order cards showing orange warning labels reading "⚠ Also on Gate X" when the same work order appears on multiple gates simultaneously.

When the same work order number is scanned at more than one gate during an audit, both cards display an orange warning label:

⚠ Also on Gate 5

This warning means the work order's hardware is split across multiple physical locations — some parts are on one rack and others are on a different rack.

Action Required
When you see a split location warning, notify the manufacturing engineer so the hardware can be reunited at the correct gate. Split hardware can cause delays and process errors.

5. Detail View

📊
Screenshot: Detail View
The Detail View showing work orders organized by Program then Part Number. Each order displays a horizontal gate progress bar with colored operation chips showing the status of each operation across its gate sequence.

The Detail View provides a detailed, per-order breakdown of gate progress. To access it, click the "Show Detail View" button below the Gate View.

Layout

Orders are grouped hierarchically:

  1. Program (top-level heading)
  2. Part Number (dark blue header bar showing part number and name)
  3. Work Orders (individual rows with gate progress bars)

Each order row has two sections:

  • Left panel (grey) — Order number, hold status, and a "Top" link to jump back to the page header
  • Right panel — A horizontal bar divided into gate columns, each containing operation chips

Operation Chip Colors

Each operation appears as a small colored chip within its gate column. The color indicates the operation's status and work department:

  • Yellow (mustard) — IN QUEUE
  • Blue — ACTIVE in a QA work department (*_QA)
  • Green — ACTIVE in SMART work department
  • Pink — ACTIVE in any other work department
  • Grey — COMPLETE or other inactive status
  • Grey (faded, 60% opacity) — PENDING operations (not yet released)

Hovering over a chip shows a tooltip with the operation number, title, status, work department, and average days at current operation. Operations with an OPER STOP condition show a red border on their chip and include the stop information in the tooltip.

Note
PENDING operations appear in the Detail View at reduced opacity to show the complete process flow, but they do not affect the Gate View or sorting calculations.

Clicking a card in the Gate View highlights the corresponding order row in the Detail View (blue outline) and scrolls to it.

6. Filters

📌
Screenshot: Filter Chips
The filter bar area showing Program filter chips (blue when selected, white when deselected) and Part Number filter chips below them. A "Show All" button appears at the start of the Program row.

Gate Tracker provides two levels of filtering: Program and Part Number. Each view (Gate View, Detail View, and Unmapped Operations) has its own independent set of filters — changing filters in one view does not affect the others.

Program Filter

  • Each program appears as a chip. Click to toggle it on (blue) or off (white).
  • The "Show All" button selects all program chips at once.
  • Program is the master filter: when a program is deselected, all its part numbers are hidden regardless of the Part Number filter state.

Part Number Filter (3-State)

Part Number chips have three states, cycled by clicking:

  1. Off (faded, low opacity) — This part number is hidden from the view
  2. On (dark blue, solid) — This part number is shown along with all other "On" parts
  3. Isolated (dark blue with bright blue outline, bold text) — Only this part number is shown; all others are hidden
Tip
Use the Isolated state when you want to focus on a single part number. Click the chip a third time to return it to the Off state and show all parts again.

7. Mobile Audit

The Mobile Audit feature generates a self-contained HTML file that can be used on a phone (iPhone with Edge, or any mobile browser) to walk the shop floor and record which work orders are at each gate.

7.1 Generating the Mobile Audit

  1. Load and process your files in Gate Tracker as usual (at minimum, the Decoder Ring and Daily Upload).
  2. Click the yellow "Generate Mobile Audit" button.
  3. A file named gate-audit-YYYY-MM-DD.html will download automatically.
  4. Email the file to yourself or transfer it to your mobile device.
  5. Open the file in your mobile browser (Edge recommended on iPhone).

7.2 Conducting an Audit

  1. Open the audit HTML file on your mobile device.
  2. Tap a gate button to select which gate you are auditing.
  3. Optionally select a technician name for that gate.
  4. For each work order on the rack, search by the last 4 digits of the order number (all orders typically share the same first 4–5 digits).
  5. Tap the matching order to add it to the audit list.
  6. If an order shows "Already on [Gate]", it was scanned at another gate. You can still add it — this creates a multi-gate situation that Gate Tracker will flag.
  7. For orders not found in the system, use the manual entry form to type the order number, with optional Part Number and Serial Number.
  8. Repeat for each gate on the floor.
  9. When finished, tap "Copy to Clipboard" to copy the audit CSV data.
  10. Open Outlook and paste the CSV data into a message body or a text file attachment.
Note
The audit tool does not use mailto links because iPhone defaults to Apple Mail. Copy the results to clipboard and paste into Outlook manually.

7.3 Uploading Audit Results

  1. On your desktop, paste the clipboard contents from the mobile audit into a new text file and save it with a .csv extension.
  2. In Gate Tracker, load this file using the "4. Mobile Audit CSV" input.
  3. Click Process (or re-process if files were already loaded) to generate the Gate View based on the audit data.

The CSV format is: Gate Number, Order No., Part No., Serial No., Technician

8. Unmapped Operations

Work orders whose part numbers do not appear in the Gate Decoder Ring are collected in the Unmapped Operations section. This section appears below the Detail View.

To view it, click the "Show Unmapped Operations" button. The section has its own:

  • Program filter — Independent from the Gate View and Detail View program filters
  • Part Number filter — Independent 3-state filter, same behavior as the Detail View part number filter

Unmapped orders are displayed in the same format as the Detail View but without gate columns (since there is no decoder ring mapping for them).

Tip
If you see part numbers appearing in the Unmapped section that should be mapped to gates, create or update the Decoder Ring for those parts using the Decoder Ring Builder tool, then re-process.

To exclude unmapped operations entirely, uncheck the "Include Unmapped Operations" checkbox before clicking Process.

9. Exporting

9.1 Print / PDF Export

  1. Click the "Print / Export PDF" button (dark grey).
  2. The browser's print dialog will open. The page is automatically formatted for printing:
    • File input controls and buttons are hidden
    • All sections (Detail View, Unmapped Operations) are expanded and visible
    • A timestamp is printed at the top of the page
    • Page breaks are inserted to avoid splitting gate sections or order cards
  3. Select your printer or "Save as PDF" and click Print.

9.2 Save Snapshot

  1. Click the green "Save Snapshot" button.
  2. A self-contained HTML file will download. This file includes:
    • All processed data embedded directly in the file
    • Full interactivity: filters, Detail View toggle, card selection all work
    • A "Proprietary — Internal Use Only" banner at the top
  3. Share the snapshot via email or save to a shared drive. Recipients can open it in any browser without needing the original CSV files.
Important
Snapshots contain proprietary manufacturing data. Follow your organization's data handling policies when sharing or storing snapshot files.

10. Troubleshooting

Symptom Solution
"File has no data rows" error after loading a file Verify the file has a header row and at least one data row. Check that the file is not empty and is in CSV format (comma or tab-delimited).
Gate View shows a placeholder message instead of gate sections A Mobile Audit CSV must be loaded for the Gate View to display gate sections. Load an audit file in input box #4 and re-process.
Orders missing from the mobile audit search Check if the order was already added to another gate — it will show a warning but can still be added. Also verify the order appears in the Daily Upload file.
Cards showing as amber "Missing from daily upload" The order was scanned during the audit but does not appear in the current daily upload data. This may mean the order was completed, canceled, or the daily upload is out of date.
Process button is disabled (greyed out) Both the Gate Decoder Ring (file #1) and Daily Upload (file #2) must be loaded before processing. Check that both show green "Loaded X rows" status messages.
Part numbers appearing in Unmapped instead of Detail View The part number is not in the Decoder Ring file. Add it to the Decoder Ring using the Decoder Ring Builder tool and re-process.
Daily Upload file loads but Process produces no results The new data source exports tab-delimited files. Gate Tracker auto-detects the delimiter, but ensure the file was not re-saved in a different format. Also verify column headers match expected names (e.g., "Order No" not "Order No.").
Row count warning after loading Daily Upload A warning appears if the file exceeds 8,000 rows. This is informational only — the file will still process. If the count seems unexpectedly high, verify you have the correct file.
Split location warnings on cards The same work order was scanned at multiple gates during the audit. Notify the manufacturing engineer to reunite the hardware at the correct gate.
Technician names not showing in gate headers Load the Gate Technicians CSV (file #3) before clicking Process. Verify the file has the correct columns: Gate Number, Gate Name, Tech Name, Priority.
